# 快速判断层（Reflex 4B / Jev）

快速判断层是可选增强。未配置、未启用或服务不可用时，CyberCode 继续使用原有的智能裁剪与模型请求流程。

## 配置

打开 **Token 优化 → 快速判断层 → 判断模型**，可以切换：

- **Reflex 4B · 本地（默认）**：新配置默认选中，端点 `http://127.0.0.1:8008/v1/systemone`，模型 `Qwen/Qwen3.5-4B`。默认不需要 API Key。
- **Jev · 云端 API**：端点 `https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`，需要 TypeSafe API Key。点击密钥输入框旁的「前往官网申请 API Key」，即可用系统浏览器打开 [TypeSafe 官方密钥管理页](https://console.typesafe.ai/keys)。

先保存配置，点击「测试已保存的连接」，再开启快速判断层和上方的「智能裁剪」。连接测试仅发送固定示例句子，不发送项目内容。默认选中 Reflex 不代表自动启用或安装模型。

两种服务的地址、模型、密钥和等待时间分别保存。切换模型立即保存选择并关闭快速判断开关，需要手动重新开启；未保存的修改必须先保存才能切换。已有旧版 Jev 配置会保留为 Jev，不会强制覆盖。

### 启动 Reflex 4B

CyberCode 接入 [Reflex 官方服务](https://github.com/kshetrajna12/reflex)，不内置 Python 推理环境或模型权重。Reflex 是基于 Qwen3.5-4B 的判断引擎，不能用普通 Ollama / OpenAI Chat Completions 地址替代。实际权重由服务启动参数决定，修改 CyberCode 的模型字段不会让服务重新加载权重。

按照上游说明准备 Python 3.12、uv 和兼容的 GPU 环境，然后在单独的终端执行：

```bash
git clone https://github.com/kshetrajna12/reflex
cd reflex
git checkout stable
uv sync
uv run reflex-serve --stable --port 8008
```

首次运行会下载模型并编译／预热。等待服务就绪后再测试连接；首次冷启动和长上下文可能超出默认 800 毫秒预算，此时本轮沿用原有裁剪。上游 stable 标签可变，部署时建议记录实际 commit。

Apple Silicon 需要包含 MPS 支持的代码版本。实测发现 `stable` 标签 `19586a1` 早于 Mac 支持，不能直接沿用上面的 checkout；先切到以下已检查的版本（需要足够统一内存）：

```bash
git fetch origin main
git checkout e21b3b23afdfeee7021a6604fa38f57e7ff5187f
uv sync --no-sources
uv run --no-sync reflex-serve --stable --model Qwen/Qwen3.5-4B --device mps --dtype float16 --port 8008
```

上游指出 4B float16 不适合 18 GB 统一内存；不要把“小模型”理解为所有 Mac 都能流畅运行。具体环境要求以 [上游安装说明](https://github.com/kshetrajna12/reflex#on-a-mac-apple-silicon) 为准。本项目在 M4 / 16 GB 上的实际启动尝试未完成推理，不能提供速度成绩；原版权重已经超过该机器的默认 MPS 预算，见[本机测试记录](./fast-judgment-local-test.md)。

Reflex 模式仅接受本机回环地址（localhost / 127.0.0.1 / ::1），不会在失败时自动切换到 Jev。如果 Reflex 使用了 `--api-key`，在当前 Reflex 配置中填写对应密钥即可。

启用后，候选旧读取／搜索结果、用户文本请求和近期活动片段会发送到配置的判断服务。密钥保存在配置目录下的 `cybercode/fast-judgment.json`，通过本地 API 只返回是否已配置，不返回密钥。密钥输入框留空表示保留；移除密钥需勾选对应选项。更换服务地址的主机时，旧密钥自动清除，除非同时明确填写新密钥。

## 浏览器任务加速

在同一配置卡片中开启「浏览器任务加速」。它和快速判断总开关默认都关闭，不要求开启智能裁剪；共用当前选择的 Jev / Reflex 服务。没有可用判断服务时，仍然使用原有的 agent-browser 工具。

开启后，主模型可调用新的 `BrowserTask`：先用现有 `agent_browser_open` 打开目标页面，再把完整子任务、限制和已知输入文字交给它。在同一浏览器会话中，快照与页面文字进入快速判断服务，一次请求同时选择操作和兼容的目标元素。

```json
{
  "goal": "在当前页面搜索 apple，并显示搜索结果",
  "fields": [{ "label": "Query", "text": "apple" }],
  "maxSteps": 8
}
```

`fields.label` 必须与实际快照中的输入框可访问名称完全一致。输入文字由主模型根据用户请求提供，Jev 不生成文本；缺少文字或遇到不支持的控件时交回主模型。

第一版支持点击按钮／链接／标签／菜单项、填写文本框、勾选／取消复选框、滚动和短暂等待。原生下拉选择、文件上传、验证码和复杂页面操作仍由主模型配合普通工具处理。

- 每次操作经过原有工具执行器、权限检查与前后置 hooks，不使用额外浏览器或绕过权限的脚本。
- 执行前在权限检查后重新读取页面；快照、URL 或页面文字变化即停止。不是浏览器层面的原子 DOM 锁，仍需主模型检查返回现场。
- 操作与目标概率均至少 0.9、置信度至少 0.8 才执行；最多每组 24 个目标，页面最多 24,000 字符。
- 默认最多 8 步、可指定至多 20 步；20 秒后不再启动下一次操作。当前浏览器调用仍受自己的超时约束。连续两步没有页面变化会停止。
- 失败返回 `handoff`、页面和步骤记录；对执行结果不明的操作标为 `attempted`，不自动重试。主模型应先检查现场，不能重复提交。
- `verify` 只表示判断模型建议完成，主模型仍须核对全部用户要求。
- 页面快照、正文、任务和已提供的输入值会发送到所选判断服务；使用 Jev 就会发送到其云端。

参考 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast) 的“操作＋目标一次判断”设计，未复制其代码或引入 Python 浏览器环境。本版由主模型预先提供输入值；上游另用小语言模型生成输入文字。

验证：已用真实 Chromium 和随项目提供的 agent-browser 跑通“填写 → 点击 → 读取结果”；判断使用本地模拟 HTTP 服务。未配置真实 Jev 密钥，因此没有官方 Jev 延迟或加速倍数的实测结果。

## 第一版的作用范围

现有确定性裁剪先执行，再由所选模型批量判断剩余的旧纯文本读取／搜索结果是否适合缩短。仅处理明确的只读工具；不会修改用户文本、助手文本、工具参数或调用关联 ID。近期消息、显式错误、含错误关键词的输出、混合媒体内容不进入快速判断候选。

- 每次至多 8 个候选，候选原文总计至多 32,000 字符；单个候选为 2,400–12,000 字符。
- 按裁剪档位保护最近 20 / 14 / 8 条消息。
- 所有用户文本请求完整发送；超过 12,000 字符则跳过本轮快速判断，避免遗漏早期约束。
- 额外发送最近 6 条消息的有限片段，帮助判断当前进展。片段外变化也会使缓存失效。
- `shorten` 概率至少 0.95 且置信度至少 0.8 才缩短；其他情况保留。
- 缩短时保留开头 700 字符、末尾 500 字符和提示标记，不生成摘要。
- 仅修改本轮请求的副本；完整会话历史仍然保留，可重新读取原文件／重新搜索。

这不是全量会话摘要替代器，也不接管工具授权、主模型选择或记忆写入。阈值是保守的初始策略，尚未用真实项目数据证明压缩质量或速度收益。

## 延迟与回退

默认最多等待 800 毫秒，可配置为 100–3000 毫秒。没有候选或未启用时不请求服务。选择 Jev 官方服务而没有 API Key 时直接回退；Reflex 本地服务不要求密钥；超时、取消、网络错误和无效概率分布都不会阻断主模型流程。每轮不重试；连续 3 次失败后冷却 30 秒。

完全相同的请求缓存 5 分钟，最多 128 条。提供商、模型、地址、密钥、开关或上下文变化后，不复用不匹配的缓存。缓存和运行计数属于各自的运行进程；配置页的统计来自提供设置 API 的服务进程，不是所有会话子进程的累计统计。连接测试的耗时也不等于真实长上下文判断耗时。

## 架构与社区参考

调用路径：模型请求准备 → 确定性裁剪 → 快速判断 → 请求副本缩短 → 主模型。

`JudgmentProvider` 将判断服务与上下文策略分离。当前提供 Jev 和 Reflex 两种 provider，共用 System One 的 Choice 批量判断协议。Reflex 连接本机推理服务，Jev 连接云端；两者共用超时、缓存、概率校验和回退策略。未来不同协议需要实现新的 provider。

设计参考（未引入这些项目的代码或依赖）：

- [Reflex](https://github.com/kshetrajna12/reflex)：本地 Qwen3.5-4B 判断引擎及服务协议。
- [TypeSafe HTTP API](https://docs.typesafe.ai/api)：请求及概率返回结构。
- [fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction)：批量判断工具历史、保护近期内容、保留调用关联和原文；本实现只缩短结果，不删除调用对。
- [jev-pruner](https://github.com/tamaratran/jev-pruner)：在主模型之外处理工具输出，使用候选门槛和异常回退。
- [jev-mcp](https://github.com/rashedInt32/jev-mcp)：另一种接法，把判断暴露为主模型主动调用的工具；本版采用运行流程自动调用。
